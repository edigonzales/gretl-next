# GRETL LSP Metadata Format

## Purpose

`gretl-lsp-metadata.json` is the machine-readable source of truth for all
GRETL LSP features: completion, hover, signature help, diagnostics, and
document symbols. It is generated by `gretl-doclet` and contains type-safe,
versioned metadata for every GRETL task and its DSL properties.

The LSP will never scrape HTML documentation. All semantic information is
sourced from this manifest.

## Location

The primary output location is:

```
gretl-doclet/build/generated/gretl-lsp-metadata/gretl-lsp-metadata.json
```

Generated by:

```bash
./gradlew generateLspMetadata
# or:
./gradlew :gretl-doclet:generateLspMetadata
```

## Schema

The JSON Schema is at:

```
gretl-doclet/src/main/resources/gretl-lsp-metadata.schema.json
```

Schema version: `1.0.0`. The version is immutable for a given schema;
breaking changes require a new version.

## Top-Level Structure

```json
{
  "schemaVersion": "1.0.0",
  "generatedAt": "2026-07-01T12:00:00Z",
  "gretlVersion": "5.0.0-SNAPSHOT",
  "source": {
    "repository": "https://github.com/sogis/gretl",
    "doclet": "gretl-doclet",
    "commit": null
  },
  "tasks": [...]
}
```

## Task Entry

Each task entry has:

| Field | Required | Description |
|-------|----------|------------|
| `name` | yes | Simple class name, e.g. `SqlExecutor` |
| `qualifiedClassName` | yes | Fully qualified class name |
| `simpleClassName` | yes | Simple class name (same as `name`) |
| `category` | no | Inferred category: `database`, `filetransfer`, `storage`, `interlis`, `transformation`, `conversion`, `network`, `other` |
| `status` | yes | One of: `stable`, `incubating`, `deprecated`, `internal`, `experimental` |
| `description` | yes | Task description from annotation or javadoc |
| `longDescription` | no | Extended description (future use) |
| `examples` | no | Array of code examples |
| `properties` | yes | Array of DSL property entries |

## Property Entry

Each property has:

| Field | Required | Description |
|-------|----------|------------|
| `name` | yes | Property/method name, e.g. `database` |
| `displayName` | no | Display name for UI |
| `kind` | yes | One of: `dsl-method-and-property`, `dsl-method`, `property`, `gradle-inherited`, `internal` |
| `valueType` | yes | Logical value type, e.g. `Connector`, `FileCollection`, `String` |
| `javaType` | no | Java type, e.g. `Property<String>` |
| `required` | yes | Whether the property is mandatory |
| `deprecated` | no | Whether the property is deprecated |
| `description` | yes | Property description |
| `file` | no | File metadata if the property references files |
| `acceptedForms` | yes | Accepted DSL forms |
| `migration` | no | Migration info for deprecated/legacy properties |
| `sqlParameterProvider` | no | Whether this property provides SQL parameters |
| `completion` | no | Completion metadata for the LSP |

## Accepted Form

Each form has:

| Field | Required | Description |
|-------|----------|------------|
| `style` | yes | `method-call`, `assignment`, `set-method`, or `unknown` |
| `signature` | yes | Human-readable signature |
| `insertText` | yes | Snippet text for completion |
| `argumentCount` | no | Number of arguments (absent for assignment) |
| `legacy` | yes | Whether this is a legacy/old form |

## File Metadata

When present, file metadata describes:

| Field | Required | Description |
|-------|----------|------------|
| `role` | yes | `input`, `output`, `input-output`, `directory-input`, `directory-output`, `unknown` |
| `extensions` | yes | Expected file extensions (starting with `.`) |
| `multiple` | no | Whether multiple files are accepted |
| `mustExist` | no | Whether files must exist on disk |

## Schema Versioning Rules

1. **Patch** (1.0.x): Add new optional fields. Backward compatible.
2. **Minor** (1.x.0): Add new enum values or change optional field semantics.
3. **Major** (x.0.0): Remove or rename required fields, change structure.

## Rules for New Task Properties

When a new GRETL task is added with `@GretlDslMethod` annotations, the doclet
automatically includes it in the metadata. The builder infers:

- **Category**: From the task name (e.g. `Sql*` → `database`)
- **Status**: Default `stable`
- **Value type**: From parameter types
- **File metadata**: From method name patterns (ends with `Files`, `File`, `Dir`)
- **SQL parameter provider**: For methods named `sqlParameters`

When automatic inference is insufficient, annotations may be extended in
future phases (e.g. `@GretlDsl`).

## Phase Status

Currently in **Phase 1**:
- Direct `@GretlDslMethod` methods only (no inherited methods yet)
- `requiredGroups` and `conflicts` fields reserved for Phase 2
- Nested DSL contexts (`sources`, `targets`, `exports`) not yet modeled
- `sensitive` flag for passwords not yet modeled
