# Decisions

## 0001 - GRETL-LSP as semantic LSP for Gradle-Groovy

**Date:** 2026-07-01  
**Status:** accepted

The LSP does not implement a full Groovy/Gradle IDE. Instead it recognizes
GRETL task blocks and evaluates them using doclet metadata.

The LSP will not:
- perform full Groovy type inference
- complete Gradle configuration phase
- live-evaluate build.gradle
- connect to databases automatically

## 0002 - Metadata from gretl-doclet is source of truth

**Date:** 2026-07-01  
**Status:** accepted

All completion, hover, diagnostic, snippet, and quick-fix features are sourced
from `gretl-lsp-metadata.json` generated by `gretl-doclet`. The LSP will not
scrape HTML documentation.

## 0003 - VS Code extension stays thin, LSP logic lives in Java

**Date:** 2026-07-01  
**Status:** accepted

The VS Code extension starts and stops the Java LSP, shows an output channel,
registers commands, and provides a tree view and webview. All GRETL semantics
live in the Java LSP.

## 0004 - Java 17 required to run Gradle 7.6.4

**Date:** 2026-07-01
**Status:** accepted

Gradle 7.6.4 does not support Java 25 (class file major version 69).
All `./gradlew` commands must run with Java 17, either via SDKMAN or
by explicitly setting `JAVA_HOME`. Example:

```bash
JAVA_HOME=/path/to/java17 ./gradlew :gretl-lsp:test
```
