= Dependency-closed runtime-image test

The runtime-image dependency-closure gate builds the current image and verifies
that Gradle can resolve the image-local Core and GeoTools distribution from a fresh
Gradle user home without remote downloads. The runtime launcher always invokes
Gradle with `--offline`; a deliberately mounted local repository remains valid.
Docker networking is deliberately independent: networked job tests use named
networks for HTTP, FTP, S3 and PostGIS fixtures.

== Local commands

Use Java 17 and the checked-in wrapper:

[source,bash]
----
./gradlew runtimeImageDependencyClosureTest --stacktrace
----

The task graph includes:

* `cleanRuntimeImageDependencyClosureState`
* `prepareRuntimeImageDependencyClosure`
* `verifyRuntimeImageDependencyClosureDistribution`
* `verifyRuntimeImageDependencyClosurePrerequisites`
* `buildRuntimeImageForTest`
* `runtimeImageDependencyClosureTest`

The distribution verifier checks the image-local Maven repository, plugin
markers, embedded GeoTools worker runtime, DuckDB extension manifest, exact
checksums and the dependency closure before Docker is invoked.

== Contract

The image contains `/opt/gretl/maven-repository` and registers no remote Gradle
repositories. A consumer using the modern `plugins {}` DSL can use the bundled
version or the exact bundled version. Other GRETL versions, non-bundled plugins
and missing transitive dependencies fail deterministically because dependency
downloads are disabled.

The closure gate uses an empty Gradle user home and the exact immutable image ID
recorded under `build/runtime-image/dependency-closure-test/`. It does not use a
host Gradle cache, source checkout, DNS block, proxy or Docker network blocking.

== Diagnostics and scope

JUnit reports are written to:

* `gretl-test-support/build/reports/tests/runtimeImageDependencyClosureTest/`
* `gretl-test-support/build/test-results/runtimeImageDependencyClosureTest/`

Failure diagnostics live below `build/runtime-image/dependency-closure-test/`.
This gate tests the modular GRETL runtime distribution. It does not migrate or
execute `sogis/gretljobs`, and its consumer fixtures use only the modern Gradle
`plugins {}` DSL.
