= Offline runtime-image test

The P0 runtime-image gate builds the image from the staged distribution and
runs consumer Gradle builds with no network and a fresh writable Gradle home.
The consumer project is the only writable bind mount. The image repository is
read-only and the container is created with Docker `NetworkMode=none`.

== Local commands

Use Java 17 and the checked-in wrapper:

[source,bash]
----
./gradlew runtimeImageOfflineTest --stacktrace
----

The task graph is intentionally explicit:

* `cleanRuntimeImageOfflineState`
* `prepareRuntimeImageOfflineDistribution`
* `verifyRuntimeImageOfflineDistribution`
* `verifyRuntimeImageOfflinePrerequisites`
* `buildRuntimeImageForOfflineTest`
* `runtimeImageOfflineTest`

The distribution verifier checks the image-local Maven repository, plugin
markers, embedded GeoTools worker runtime, DuckDB extension manifest, exact
checksums and the dependency closure before Docker is invoked.

== Offline contract

The launcher uses the image init script and every offline consumer receives
`--offline`, `--no-daemon` and `--console=plain`. Remote repositories are not
registered by the strict image profile. The test does not use `mavenLocal()`,
`flatDir`, a Gradle wrapper, a source checkout, host `.gradle` or host `.m2`.

The image contains a bundled GRETL repository at
`/opt/gretl/maven-repository`. `/work/gradle-home` is a fresh tmpfs for each
container. `/work/project` is the writable consumer project. The image root
and bundled distribution are read-only.

== Diagnostics and troubleshooting

JUnit reports are written to:

* `gretl-test-support/build/reports/tests/runtimeImageOfflineTest/`
* `gretl-test-support/build/test-results/runtimeImageOfflineTest/`

Set `-DgretlOfflineTestKeepDiagnostics=true` to retain masked Docker commands,
container inspection and stdout/stderr under
`build/runtime-image/offline-test/diagnostics/` after a failed run. A missing
Docker daemon is a hard failure; the gate is never silently skipped.

== Scope

This gate tests the modular GRETL runtime distribution. It does not migrate
or execute `sogis/gretljobs`, and its consumer fixtures use only the modern
Gradle `plugins {}` DSL.
